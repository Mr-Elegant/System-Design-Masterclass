Domain-Driven Design (DDD) Aggregates & Saga Orchestrator

LLD MACHINE CODING ARCHITECTURE Domain-Driven Design (DDD) Aggregates & Saga Orchestrator
Low-Level Architecture: Encapsulates domain business invariants within rich entity models, managed by decoupled service orchestrators adhering to Gang of Four (GoF) structural and behavioral design patterns.
DDDSaga PatternMicroservices

Tactical DDD separates Entities (identity), Value Objects (immutable attributes), and Aggregates (consistency boundaries). The Saga Pattern manages distributed transactions using compensation handlers.

JavaScript — Saga Orchestrator & Compensating Rollback
class SagaStep {
    constructor(name, execute, compensate) {
        this.name = name; this.execute = execute; this.compensate = compensate;
    }
}

class SagaOrchestrator {
    #steps = [];
    addStep(step) { this.#steps.push(step); return this; }

    async run(context) {
        const executed = [];
        try {
            for (const step of this.#steps) {
                console.log(`[SAGA EXEC] ${step.name}`);
                await step.execute(context);
                executed.push(step);
            }
            console.log("✅ [SAGA SUCCESS] All steps committed!");
        } catch (err) {
            console.error(`❌ [SAGA FAILED] Error: ${err.message}. Starting Compensation...`);
            for (let i = executed.length - 1; i >= 0; i--) {
                const step = executed[i];
                console.log(`[SAGA ROLLBACK] Compensating ${step.name}...`);
                await step.compensate(context);
            }
            console.log("🛑 Saga Compensation Complete.");
        }
    }
}

const saga = new SagaOrchestrator()
    .addStep(new SagaStep("ReserveInventory", ctx => console.log("Inventory reserved"), ctx => console.log("Inventory unreserved")))
    .addStep(new SagaStep("ChargeCard", ctx => { throw new Error("Card declined!"); }, ctx => console.log("Card refunded")));

saga.run({});

Problem 22: Design Workflow Engine (State / Command Pattern)

LLD MACHINE CODING ARCHITECTURE Problem 22: Design Workflow Engine (State / Command Pattern)
Low-Level Architecture: Encapsulates domain business invariants within rich entity models, managed by decoupled service orchestrators adhering to Gang of Four (GoF) structural and behavioral design patterns.
State/CommandWorkflow EngineStep Execution

Workflow Engine executing multi-step business DAG workflows with conditional branching and automated step retries.

JavaScript — DAG Workflow Engine Implementation
class WorkflowStep {
    constructor(name, action) {
        this.name = name;
        this.action = action;
    }
}

class WorkflowEngine {
    #steps = [];

    addStep(step) { this.#steps.push(step); return this; }

    async executeWorkflow(context = {}) {
        console.log("⚙️ [WORKFLOW ENGINE START]");
        for (const step of this.#steps) {
            console.log(`▶ Executing Step: ${step.name}`);
            context[step.name] = await step.action(context);
        }
        console.log("🏁 [WORKFLOW ENGINE COMPLETE] Result:", context);
        return context;
    }
}

const wf = new WorkflowEngine()
    .addStep(new WorkflowStep("validateInput", ctx => ({ valid: true })))
    .addStep(new WorkflowStep("processOrder", ctx => ({ orderId: "ORD_77" })));

wf.executeWorkflow();

Problem 23: Design Rule Engine (Specification / Strategy Pattern)

LLD MACHINE CODING ARCHITECTURE Problem 23: Design Rule Engine (Specification / Strategy Pattern)
Low-Level Architecture: Encapsulates domain business invariants within rich entity models, managed by decoupled service orchestrators adhering to Gang of Four (GoF) structural and behavioral design patterns.
SpecificationRule EngineStrategy

Rule Engine evaluating boolean logical expressions (`AND`, `OR`, `NOT`) against domain entities dynamically.

JavaScript — Specification Pattern Rule Engine
class Specification {
    isSatisfiedBy(candidate) { throw new Error("Abstract method"); }
    and(other) { return new AndSpecification(this, other); }
    or(other) { return new OrSpecification(this, other); }
}

class AndSpecification extends Specification {
    constructor(one, two) { super(); this.one = one; this.two = two; }
    isSatisfiedBy(c) { return this.one.isSatisfiedBy(c) && this.two.isSatisfiedBy(c); }
}

class OrSpecification extends Specification {
    constructor(one, two) { super(); this.one = one; this.two = two; }
    isSatisfiedBy(c) { return this.one.isSatisfiedBy(c) || this.two.isSatisfiedBy(c); }
}

class MinAgeSpec extends Specification {
    constructor(minAge) { super(); this.minAge = minAge; }
    isSatisfiedBy(user) { return user.age >= this.minAge; }
}

class HasCreditCardSpec extends Specification {
    isSatisfiedBy(user) { return user.hasCreditCard === true; }
}

const eligibleUserSpec = new MinAgeSpec(18).and(new HasCreditCardSpec());
console.log("User Eligible:", eligibleUserSpec.isSatisfiedBy({ age: 21, hasCreditCard: true }));
