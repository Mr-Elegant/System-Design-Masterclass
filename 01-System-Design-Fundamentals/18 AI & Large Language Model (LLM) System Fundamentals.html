Distributed GPU Parallelism Mesh (TP + PP + ZeRO/FSDP)
GPU INFRASTRUCTURE
💡 Key Architecture Takeaway: 3D Parallelism coordinates Tensor Parallelism (TP) across intra-node NVLink (900 GB/s), Pipeline Parallelism (PP) across inter-node InfiniBand (400 Gbps), and ZeRO-3/FSDP Data Parallelism to scale models beyond single-GPU VRAM limits.

1. The Hardware Physics & The Memory Wall

State-of-the-art Large Language Models (e.g., Llama-3 70B, GPT-4 with ~1.8 Trillion mixture-of-experts parameters) fundamentally challenge modern computing hardware. To design AI systems at scale, an architect must understand the physical constraints of GPU memory bandwidth, compute FLOPS, and interconnect topology.

A. The Roofline Model & Arithmetic Intensity

Every GPU workload falls into one of two operational regimes based on its Arithmetic Intensity (FLOPs per byte of memory transfer):

Arithmetic Intensity = Total Compute Operations (FLOPs) / Total Memory Access (Bytes)

  • Compute-Bound (Prefill Phase): In the prompt processing phase, all tokens in the prompt are processed concurrently as large matrix multiplications (Q, K, V projections). High arithmetic intensity (>> 100 FLOPs/byte) saturates GPU Tensor Cores (e.g., Nvidia H100 SXM achieving ~1,979 TFLOPs of FP16 compute).
  • Memory-Bandwidth-Bound (Decoding Phase): In the token generation phase, the GPU fetches the entire model's weights (~140GB for a 70B model in FP16) from High Bandwidth Memory (HBM3) to generate just one token. The arithmetic intensity is tiny (~1 FLOP/byte). Generation speed is strictly bottlenecked by HBM memory bandwidth (3.35 TB/s on H100):
    Max Generation Speed = HBM Bandwidth / Model Weight Size = 3,350 GB/s / 140 GB ≈ 23.9 tokens/sec per GPU.

2. Tensor Parallelism (TP - Megatron-LM)

Tensor Parallelism partitions the weight matrices of individual Linear and Self-Attention layers across multiple GPUs within the same server node.

Column-Parallel & Row-Parallel Architecture

A standard Multi-Head Attention block consists of Q, K, V projection matrices followed by an Output projection matrix W_O:

  1. Column-Parallel (Q, K, V Projections): The weight matrix W is split along its columns into N shards (W = [W_1 | W_2 | ... | W_N]). Each GPU computes Y_i = X * W_i independently without inter-GPU communication.
  2. Row-Parallel (Output Projection W_O): The output matrix is split along its rows (W_O = [W_O,1; W_O,2; ...; W_O,N]). Each GPU computes its partial matrix product Z_i = Y_i * W_O,i.
  3. All-Reduce Sum: The final output is aggregated via an All-Reduce collective communication: Z = Sum(Z_i).
# PyTorch Conceptual Megatron-LM Tensor Parallel Layer
import torch
import torch.nn as nn
import torch.distributed as dist

class ColumnParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, world_size, rank):
        super().__init__()
        self.split_out = out_features // world_size
        self.weight = nn.Parameter(torch.empty(in_features, self.split_out))
        self.rank = rank

    def forward(self, x):
        # Local matrix multiplication without communication
        return torch.matmul(x, self.weight)

class RowParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, world_size, rank):
        super().__init__()
        self.split_in = in_features // world_size
        self.weight = nn.Parameter(torch.empty(self.split_in, out_features))

    def forward(self, x):
        local_out = torch.matmul(x, self.weight)
        # Synchronize partial results across all GPUs in the TP group
        dist.all_reduce(local_out, op=dist.ReduceOp.SUM)
        return local_out

3. Pipeline Parallelism (PP) & The 1F1B Schedule

Pipeline Parallelism distributes consecutive transformer layers across distinct server nodes (e.g., Node 0 holds Layers 1-20, Node 1 holds Layers 21-40). To prevent massive idle time ("the pipeline bubble"), training mini-batches are divided into m micro-batches.

Mathematical Bubble Fraction:

F_bubble = (p - 1) / (m + p - 1)

Where p is the number of pipeline stages and m is the number of micro-batches (m ≥ 4p is typical in production to reduce bubble overhead to < 15%). In the 1F1B (One Forward, One Backward) schedule, each stage alternates between computing one forward micro-batch and one backward micro-batch, keeping peak activation memory bounded to p micro-batches.

LLM Inference Optimization &amp;amp;amp; KV-Cache Architecture

vLLM PagedAttention Virtual Memory Block Mapping
INFERENCE ENGINE
💡 Key Architecture Takeaway: PagedAttention divides contiguous logical token sequences into non-contiguous physical GPU memory pages, eliminating 96% of VRAM fragmentation and enabling 4x higher request concurrency.

1. Full VRAM Allocation Breakdown in Production Serving

When deploying an LLM inference server (vLLM / TensorRT-LLM), total GPU VRAM is partitioned into four critical segments:

VRAM_Total = M_Weights + M_KV_Cache + M_Activations + M_Workspace

  • Model Weights (M_Weights): For Llama-3 70B in FP16 (2 bytes/param), 70 * 10^9 * 2 = 140 GB. In INT4 AWQ (0.5 bytes/param), this shrinks to 35 GB.
  • KV-Cache Pool (M_KV_Cache): All remaining VRAM after loading weights is allocated to the dynamic KV-cache block pool.
  • Activation Memory (M_Activations): Temporary tensors created during the forward attention pass (Batch_size * Seq_len * Hidden_dim).

2. Python PagedAttention Block Manager Implementation

The following production Python engine illustrates how vLLM allocates non-contiguous physical GPU blocks to logical request sequences:

from typing import List, Dict
import math

class PhysicalGPUBlock:
    def __init__(self, block_number: int, block_size: int = 16):
        self.block_number = block_number
        self.block_size = block_size
        self.ref_count = 0  # For Copy-on-Write sharing

class BlockTableManager:
    def __init__(self, total_gpu_blocks: int, block_size: int = 16):
        self.block_size = block_size
        self.free_blocks: List[PhysicalGPUBlock] = [
            PhysicalGPUBlock(i, block_size) for i in range(total_gpu_blocks)
        ]
        # Maps request_id -> list of PhysicalGPUBlocks
        self.block_tables: Dict[str, List[PhysicalGPUBlock]] = {}

    def allocate_prompt(self, request_id: str, prompt_tokens: int) -> bool:
        num_blocks_needed = math.ceil(prompt_tokens / self.block_size)
        if len(self.free_blocks) < num_blocks_needed:
            return False  # Trigger KV-cache preemption or swap to CPU
        
        allocated = []
        for _ in range(num_blocks_needed):
            block = self.free_blocks.pop()
            block.ref_count = 1
            allocated.append(block)
            
        self.block_tables[request_id] = allocated
        return True

    def append_token(self, request_id: str, current_token_count: int) -> PhysicalGPUBlock:
        table = self.block_tables[request_id]
        if current_token_count % self.block_size == 1:
            # Need a new physical block for the next token page
            if not self.free_blocks:
                raise MemoryError("GPU VRAM Full: Preemption required")
            new_block = self.free_blocks.pop()
            new_block.ref_count = 1
            table.append(new_block)
        return table[-1]

    def free_request(self, request_id: str):
        if request_id in self.block_tables:
            for block in self.block_tables[request_id]:
                block.ref_count -= 1
                if block.ref_count == 0:
                    self.free_blocks.append(block)
            del self.block_tables[request_id]

3. FlashAttention-3: SRAM Block Tiling & Online Softmax

Standard attention materializes the massive S * S attention matrix in slow HBM (O(S^2) memory reads and writes). FlashAttention tiles the Query, Key, and Value matrices into fast on-chip SRAM (O(1) memory overhead):

  • Online Softmax Rescaling: Computes softmax incrementally across blocks using local running maximums (m) and normalizers (l):
    m_new = max(m_prev, m_block), l_new = l_prev * exp(m_prev - m_new) + sum(exp(x_i - m_new))
  • Hardware Asynchrony: FlashAttention-3 utilizes Nvidia Hopper Tensor Memory Accelerator (TMA) and FP8 Tensor Core hardware pipelines to overlap computation with memory movement.

Speculative Decoding &amp;amp;amp; Model Quantization

1. Speculative Decoding Rejection Sampling Algorithm

Speculative decoding guarantees 100% mathematical output fidelity (identical probability distribution as the target model) while breaking the memory bandwidth wall.

The Verification Protocol:

import numpy as np

def verify_speculative_tokens(draft_tokens, draft_probs, target_probs):
    """
    draft_tokens: List of K speculative tokens from draft model (e.g. Llama-3 8B)
    draft_probs: Probabilities q(x) from draft model
    target_probs: Probabilities p(x) from target model (e.g. Llama-3 70B)
    """
    accepted_tokens = []
    
    for i, token in enumerate(draft_tokens):
        p = target_probs[i][token]
        q = draft_probs[i][token]
        
        # Acceptance probability alpha = min(1, p/q)
        alpha = min(1.0, p / max(q, 1e-8))
        r = np.random.uniform(0.0, 1.0)
        
        if r <= alpha:
            accepted_tokens.append(token)
        else:
            # Token rejected: Sample recovery token from normalized max(0, p - q)
            rescaled_p = np.maximum(0, target_probs[i] - draft_probs[i])
            rescaled_p /= np.sum(rescaled_p)
            recovery_token = np.random.choice(len(rescaled_p), p=rescaled_p)
            accepted_tokens.append(recovery_token)
            break  # Stop verification on first rejection
            
    return accepted_tokens

2. Advanced Quantization Mechanics: SmoothQuant & AWQ

A. SmoothQuant (INT8 Weight & Activation Quantization)

Activation tensors in LLMs exhibit extreme channel outliers (e.g., 100x larger than normal values in 0.1% of channels), causing naive INT8 activation quantization to collapse model accuracy. SmoothQuant mathematically migrates the quantization difficulty from activations to weights:

Y = (X * diag(s)^-1) * (diag(s) * W) = X_hat * W_hat

Where migration scale s_j = max(|X_j|)^alpha / max(|W_j|)^(1-alpha) (with hyperparameter alpha = 0.5).

B. AWQ (Activation-aware Weight Quantization - INT4)

AWQ observes that not all weights are equally important: protecting the top 1% salient weight channels (determined by average activation magnitude) prevents perplexity degradation. AWQ scales salient channels by factor s > 1 before per-group INT4 quantization without requiring expensive backpropagation retraining.

Semantic Vector Caching &amp;amp;amp; Prompt Engineering Systems

1. Enterprise Semantic Caching Architecture (Redis Vector Cache)

Semantic caching saves over 40% of LLM compute costs by returning cached responses for semantically identical queries.

Mathematical Similarity Threshold & Metric Budget:

Given incoming query vector q and cached vector c:

Cosine Similarity(q, c) = (q . c) / (||q||_2 * ||c||_2)

  • Similarity ≥ 0.96: Exact semantic match. Return cached answer immediately with zero LLM invocation (Latency < 15ms).
  • 0.88 ≤ Similarity < 0.96: Partial match. Use cached answer as an in-context few-shot demonstration in the prompt to reduce output token generation time.
  • Similarity < 0.88: Cache miss. Dispatch request to inference cluster.

2. RadixAttention: Automatic KV-Cache Tree Prefix Sharing

RadixAttention maintains an in-memory Radix Tree (compact Trie) of token sequences in the inference engine:

  • System Prompt Caching: When 1,000 users send prompts sharing a 2,000-token system instruction, the system prompt's KV-cache is computed exactly once and shared across all 1,000 requests.
  • Multi-Turn Chat Reuse: In a 10-turn chat, Turn N reuses the KV blocks of Turns 1 ... N-1 directly from memory, reducing TTFT from 1,200ms to < 60ms.
