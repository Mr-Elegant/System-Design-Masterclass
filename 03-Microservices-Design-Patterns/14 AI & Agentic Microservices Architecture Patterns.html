💡 Key Architecture Takeaway: The AI Gateway abstracts downstream LLM providers, providing token-bucket rate limits, PII guardrails, and automated fallback chains across Anthropic, OpenAI, and self-hosted vLLM clusters.

1. The Problem: Direct LLM Coupling in Microservices

When multiple microservices independently invoke external LLM providers (e.g., OpenAI, Anthropic), significant architectural liabilities emerge:

  • Cost & Rate Limit Fragmentation: Individual services trigger HTTP 429 errors without central token budgeting.
  • Outage Fragility: An outage in a single AI provider brings down entire customer checkout or user onboarding flows.
  • PII & Security Leaks: Unsanitized database rows containing credit card numbers or personal identity data are transmitted directly to external third parties.

2. Production Redis Lua Rate Limiter (Dual RPM + TPM Bucket)

LLM providers rate limit accounts on both Requests Per Minute (RPM) and Tokens Per Minute (TPM). The AI Gateway enforces both constraints atomically in Redis:

-- Redis Lua Script: Atomic Dual RPM and TPM Rate Limiter
local user_key = KEYS[1]
local max_rpm = tonumber(ARGV[1])
local max_tpm = tonumber(ARGV[2])
local estimated_tokens = tonumber(ARGV[3])
local now = tonumber(ARGV[4])

local req_count = redis.call('ZCOUNT', user_key..':req', now - 60, now)
if req_count >= max_rpm then
    return {0, "RPM_EXCEEDED"}
end

local token_count = redis.call('GET', user_key..':tokens')
if token_count and (tonumber(token_count) + estimated_tokens > max_tpm) then
    return {0, "TPM_EXCEEDED"}
end

-- Record Request and Token Usage
redis.call('ZADD', user_key..':req', now, now)
redis.call('EXPIRE', user_key..':req', 65)

redis.call('INCRBY', user_key..':tokens', estimated_tokens)
redis.call('EXPIRE', user_key..':tokens', 60)

return {1, "ALLOWED"}

3. Dynamic Multi-Provider Fallback & Circuit Breaking

The gateway coordinates an intelligent circuit breaker hierarchy:

  1. Tier 1 (High Capability): Claude 3.5 Sonnet (Primary).
  2. Tier 2 (High Concurrency Fallback): GPT-4o (Invoked if Tier 1 latency > 2.5s or returns 5xx/429).
  3. Tier 3 (Self-Hosted Fallback): Internal vLLM cluster hosting Llama-3 70B (Guarantees 100% uptime even during total internet/SaaS outages).

1. ReAct: Complete Python Execution Loop

The ReAct pattern alternates between reasoning and action execution. Below is a production Python implementation with tool sandboxing:

import re

class ReActAgent:
    def __init__(self, llm_client, tools: dict, max_steps: int = 6):
        self.llm = llm_client
        self.tools = tools
        self.max_steps = max_steps

    def run(self, user_prompt: str) -> str:
        scratchpad = f"Question: {user_prompt}\n"
        
        for step in range(self.max_steps):
            prompt = scratchpad + "Thought: "
            response = self.llm.generate(prompt, stop=["\nObservation:"])
            scratchpad += "Thought: " + response + "\n"
            
            # Check for final answer
            if "Final Answer:" in response:
                return response.split("Final Answer:")[1].strip()
                
            # Parse Action: tool_name[arg]
            action_match = re.search(r"Action:\s*([a-zA-Z0-9_]+)\[(.*?)\]", response)
            if not action_match:
                scratchpad += "Observation: Invalid action format. Use Action: tool_name[arg]\n"
                continue
                
            tool_name, tool_arg = action_match.groups()
            if tool_name in self.tools:
                try:
                    observation = self.tools[tool_name](tool_arg)
                except Exception as e:
                    observation = f"Error executing {tool_name}: {str(e)}"
            else:
                observation = f"Tool {tool_name} not found."
                
            scratchpad += f"Observation: {observation}\n"
            
        return "Failed to resolve goal within maximum step limit."

1. Three-Tier Memory Architecture

  • Working Memory: In-context system prompt scratchpad (e.g., user identity, immediate goal status).
  • Episodic Recall Memory: Pinecone/Milvus dense vectors capturing past dialogues with temporal exponential decay:

  • Archival Knowledge Graph (GraphRAG): Entity-relation triplets extracted by an offline LLM pipeline into Neo4j, enabling multi-hop associative recall.

1. LoRA Adapter Hot-Swapping Architecture

In low-rank adaptation, the weight update matrix is decomposed into two low-rank matrices: $W_{ ext{new}} = W_{ ext{base}} + rac{lpha}{r} (A \cdot B)$. In a production vLLM cluster, the base model is frozen in GPU memory, while dynamic LoRA weights (only 50MB-200MB each) are loaded on-the-fly per request based on tenant header: X-LoRA-Adapter: legal-v3.

2. RAG Triad Automated Evaluation Metrics

  • Context Relevance: Proportion of retrieved chunks relevant to the user query.
  • Groundedness (Faithfulness): Ratio of generated claims directly verified by retrieved context.
  • Answer Relevance: Semantic alignment between the user's intent and final output.
